The process

Three steps. A clearer picture.

No security expertise required to get started. Every finding should explain what was observed, why it deserves attention, and what to check next.

01 / CONNECT ↗

Connect a repository

Give QIRA permission to read the GitHub workflows you choose. It won't edit code or change infrastructure.

02 / UNDERSTAND ◎

See what stands out

Understand review candidates in everyday language. Every result includes its source and an explanation of uncertainty.

03 / RECHECK ✓

Keep a record

Compare configuration evidence after a change and export a reproducible report. A cleared indicator is not proof of safety.

What deserves a closer look?

      

      

       
Explicit safeguards observed

       
These are positive declarations in the reviewed workflow files—not independently verified effective permissions, organization policy, or proof that the workflows are secure.

       

      

      

       
Write-level permission inventory

       
These workflow files declare at least one write-level GitHub Actions permission. This is an authorization inventory, not an additional vulnerability finding. Some write permissions, including id-token: write, are intentionally used for OIDC publishing.
